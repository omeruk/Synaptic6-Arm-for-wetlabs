# Synaptic6 – Arm for wetlabs

A 6-axis robot arm I'm designing for wet lab work (moving tubes and plates, later pipetting). It's a CAD and simulation project, I'm not building the hardware, so everything here is design, calculation and sim.

**Status:** work in progress.

- [x] Requirements and first torque estimate
- [x] Actuator choice (CubeMars AK for the big joints)
- [x] Kinematics: FK, closed-form IK (8 solutions), Jacobian, workspace
- [x] Gravity / dynamic torque model with checks, actuator selection
- [x] Skeleton definition (`docs/skeleton.md`) and a Fusion 360 script for it
- [ ] Full assembly in Fusion 360 (real masses back into the model)
- [ ] Link stress and deflection (Fusion simulation)
- [ ] URDF + simulation (MuJoCo or PyBullet)
- [ ] AprilTag visual servoing in sim

## Why this exists

I wanted one project that covers the whole chain: mechanical design, motor selection, kinematics, vision and simulation. Wet labs are a good target because the arm works near people, carries light loads, and needs repeatable positioning more than raw strength.

## Design targets

| | |
|---|---|
| Reach | 480 mm from the shoulder (xArm 7 is 700 mm, I went smaller on purpose, see below) |
| Payload | 0.5 kg plus a 0.2 kg gripper |
| Repeatability goal | ≲ 0.5 mm, helped by camera feedback |
| Big joints (J2, J3) | CubeMars AK-series |
| Wrist (J4–J6) | small, light actuators (Dynamixel-class) |
| Sensing | wrist camera + AprilTags on the workspace and tools |

Why not 700 mm: the shoulder torque goes up 2–3x with that reach, which means heavier motors, which load the shoulder even more. A bench-top wet lab doesn't need it, and shorter is stiffer.

## Current numbers

Full tables and plots are in [`docs/results.md`](docs/results.md), generated by `analysis/run_analysis.py`. Summary for the 0.5 kg case (1.5x safety factor, 5 rad/s² acceleration):

| Joint | needs rated | needs peak | pick |
|---|---|---|---|
| J2 shoulder | 8.0 Nm | 10.6 Nm | AK80-9 |
| J3 elbow | 3.4 Nm | 4.7 Nm | AK80-9 |
| J4, J5 | 0.9 Nm | 1.2–1.3 Nm | XM430-class |

The shoulder margin on rated torque is small (~12 %), so a heavier payload or a longer arm pushes it to the next actuator size. Payload sweep is in the results file.

## How I checked the model

`pytest` runs these (see `tests/test_model.py`):

- FK at known poses (zero pose, stretched-out pose)
- IK: all 8 solutions go back through FK to the same pose, 500 random poses
- Jacobian vs finite differences
- Gravity torque vs the gradient of potential energy (an independent way to get the same numbers)
- Stretched-out pose vs a closed-form hand calculation
- Mass matrix symmetric, positive definite, and consistent with kinetic energy from FK velocities

The hand-calc test actually caught a bug in my first mass model (the tool frame already includes `d6`, so I had put the gripper and payload 100 mm too far out).

## Known limits of the model

- Links are point masses: no rotational inertia, no Coriolis terms. J1 and J6 torques are therefore lower bounds and not sized yet.
- Actuator numbers are from memory of the datasheets and need checking.
- Link structure masses (0.12 and 0.10 kg) are guesses until the CAD exists.
- No table or self-collision check, so the workspace plot includes poses below the base plate.
- Random search for the worst case, plus the obvious stretched pose and a local refinement. Not a proof of the global maximum.

## Idea for later: swappable end effectors

A standard flange (magnets + alignment pins, a few pogo pins for power/data) with an AprilTag on each tool and on its dock. The arm finds the dock with the camera, the pins correct the last millimetre. Tools: gripper, tube/plate gripper, pipette, sensor.
